## Summary

Build an interactive conversational CLI chat agent using `pydantic-ai` powered by Google Vertex AI (`gemini-3.8-flash`) authenticated via API key from `.env`. The agent operates in a single-turn conversational loop, answering natural language questions about extracted entities strictly through read-only database query tools. It enforces guardrails by denying out-of-scope requests, barring access to pipeline execution/job data, reporting missing information without hallucinating, and retrying up to 3 times on transient errors.

## Technical Context

**Language/Version**: Python 3.12+ (Ubuntu Linux on WSL)  
**Primary Dependencies**: `pydantic-ai>=0.0.18` (or `pydantic-ai-slim[google]`), `google-genai>=0.1.1`, `typer>=0.12.0`, `motor>=3.5.0`, `pydantic>=2.7.0`, `loguru>=0.7.3`  
**Storage**: MongoDB 7.0+ (querying `entities`, `occurrences`, and `documents` collections asynchronously via Motor; strictly barring `jobs` collection)  
**Testing**: Human-authored tests only per Constitution Principle VI; interactive verification via CLI  
**Target Platform**: Ubuntu Linux under WSL on Windows 11  
**Project Type**: Conversational AI Agent & Typer CLI  
**Performance Goals**: <4s response turnaround time on typical entity queries  
**Constraints**: Single-turn interaction (no conversation history retained); strict tool-grounding (no internal model knowledge or hallucinations); case-insensitive matching; max 3 retries on transient errors; zero access to job-level data  
**Scale/Scope**: Database-wide entity inspection covering all ingested documents and occurrences
